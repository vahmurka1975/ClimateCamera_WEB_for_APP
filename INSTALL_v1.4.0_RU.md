# Установка ClimateCamera WEB for APP v1.4.0

Статус: кандидат для стендовой проверки. Компиляция прошла; на физическом ESP32 прошивка не испытывалась. Работа ведётся только на базе https://github.com/vahmurka1975/ClimateCamera_WEB_for_APP. Изменения в GitHub не отправлялись.

## Первый переход с предыдущей версии

Нужна USB-прошивка с таблицей partitions_140.csv. Обычное OTA не меняет таблицу разделов и не является достаточным способом первого перехода. Сначала сохраните продукты и настройки доступным в прежней версии способом, а при необходимости — полный дамп flash. Совместимость миграции данных на реальном устройстве не проверена.

Отключите силовые нагрузки. Установите esptool (`python -m pip install esptool`). Из каталога firmware выполните (синтаксис esptool 4.x):

`python -m esptool --chip esp32 --port COM_PORT --baud 460800 write_flash 0x1000 bootloader.bin 0x8000 partitions.bin 0xe000 boot_app0.bin 0x10000 firmware.bin`

COM_PORT замените портом вашего контроллера. Не используйте erase_flash при попытке сохранить NVS. Указанные четыре файла не записывают область NVS 0x9000–0xdfff. Тем не менее перед обновлением обязательна резервная копия; это не гарантия миграции. Регион 0x3d0000–0x3fffff используется как cc_store вместо прежнего SPIFFS; прежняя файловая система в этой области не сохраняется при использовании нового хранилища.

Объединённый образ намеренно не включён: запись такого образа целиком может затронуть промежуточную область NVS. В архиве есть отдельные компоненты для адресной USB-прошивки.

## Последующие обновления

После установки и проверки правильной таблицы разделов для OTA используется только firmware.bin. Bootloader, partitions и boot_app0 через форму OTA не загружаются.

## Первый вход

Если домашняя Wi-Fi-сеть не задана, подключитесь к ClimateCamera-AP, пароль Climate120!, затем откройте http://192.168.4.1/setup. Начальные учётные данные: admin / ChangeMe_Admin_2026!; наблюдатель: viewer / ChangeMe_View_2026!. Немедленно смените пароли. При собственном Secrets.h начальные значения берутся из него; сохранённый профиль NVS имеет приоритет. При сбое подключения к настроенной сети резервная AP предусмотрена через 45 секунд при включённом резервировании.

## Обязательная стендовая проверка

Проверьте вход и запрет административных операций наблюдателю; неверный пароль, токен и подтверждение; сохранение сети, IP и обеих учётных записей после перезапуска; все три варианта backup/restore; отклонение повреждённого файла; оба сброса; сохранение продуктов при сбросе только настроек; миграцию старой базы; безопасное отключение реле и восстановление при прерывании питания. После операций управления предусмотрен запуск с остановленной автоматикой и ручное включение.

Копии настроек содержат пароли в открытом виде. Формат .ccbackup привязан к версии структур прошивки и не является универсальным JSON. HTTP Basic Auth не шифрует трафик: используйте доверенную локальную сеть или VPN; не публикуйте HTTP-порт в интернете. Пока стендовые проверки не завершены, не используйте сборку для автономного управления силовыми нагрузками.

Переход выполняйте через USB, а не через OTA: в v1.4.0 изменена таблица разделов ESP32. При этом не используйте erase_flash — он удалит NVS, где находятся продукты и история взвешиваний.
Важно: миграция базы продуктов в v1.4.0 предусмотрена в коде, но на физическом контроллере не проверялась. Поэтому сначала обязательно сделайте резервную копию.
1. Подготовьте старую v1.3.3
До прошивки v1.4.0:
Запустите устройство на v1.3.3.
Проверьте, что продукты и история взвешиваний отображаются корректно.
Если старая Web-версия позволяет экспортировать продукты — сохраните отдельную копию продуктов.
Дополнительно сделайте полный дамп Flash ESP32.
Установите esptool:
PowerShell

Копировать код

py -m pip install esptool

Узнайте размер Flash:
PowerShell

Копировать код

py -m esptool --chip esp32 --port COM5 flash_id

Замените COM5 на порт вашего контроллера. В выводе будет указано, например:
Plaintext

Копировать код

Detected flash size: 4MB

Для микроконтроллера с Flash 4 МБ сохраните полный образ:
PowerShell

Копировать код

py -m esptool --chip esp32 --port COM5 read_flash 0x000000 0x400000 v1.3.3_full_flash.bin

Для Flash 8 МБ вместо 0x400000 используйте 0x800000.
Этот дамп нужен для возврата к исходному состоянию, если миграция не пройдёт корректно.
2. Подготовьте файлы v1.4.0

3. Прошейте v1.4.0 без очистки Flash
Из каталога с файлами прошивки выполните:
PowerShell

Копировать код

py -m esptool --chip esp32 --port COM5 --baud 460800 write_flash `
  0x1000 bootloader.bin `
  0x8000 partitions.bin `
  0xe000 boot_app0.bin `
  0x10000 firmware.bin

В командной строке Windows вместо COM5 укажите фактический порт.
Если на скорости 460800 появятся ошибки связи, повторите с меньшей скоростью:
PowerShell

Копировать код

py -m esptool --chip esp32 --port COM5 --baud 115200 write_flash `
  0x1000 bootloader.bin `
  0x8000 partitions.bin `
  0xe000 boot_app0.bin `
  0x10000 firmware.bin

Эта команда записывает загрузчик, таблицу разделов и прошивку, но не должна очищать область NVS:
Plaintext

Копировать код

0x9000–0xdfff

Именно поэтому продукты из старого namespace cc_prod должны сохраниться.
