# Установка и проверка v1.4.1

Это кандидат для стендовой проверки, не испытанный на физическом ESP32. Сначала сделайте резервную копию исходной прошивки и продуктов.

При первом переходе нужна USB-прошивка с новой таблицей разделов. Вариант: PlatformIO `pio run -e esp32dev -t upload`. Подготовленный комплект содержит bootloader.bin, partitions.bin, boot_app0.bin, firmware.bin. Адреса: 0x1000, 0x8000, 0xe000, 0x10000. Команда: `python -m esptool --chip esp32 --port COM_PORT --baud 460800 write_flash 0x1000 bootloader.bin 0x8000 partitions.bin 0xe000 boot_app0.bin 0x10000 firmware.bin`. Замените COM_PORT. Не используйте erase_flash, если нужно сохранить продукты и NVS.

После настройки таблицы дальнейшие обновления возможны OTA файлом firmware.bin. NVS и оба приложения сохраняют прежние адреса. Старый регион SPIFFS заменён хранилищем управления, поэтому откат на прошивки, использующие SPIFFS, может уничтожить его.

Без заданной домашней сети подключитесь к ClimateCamera-AP, пароль Climate120!, откройте http://192.168.4.1/setup. Логин admin, пароль ChangeMe_Admin_2026!. Наблюдатель viewer, пароль ChangeMe_View_2026!. После изменения сети/паролей повторите вход с новыми данными. Если использован личный Secrets.h, начальные пароли берутся из него.

Стендовая проверка обязательна: 1) миграция всех 30 продуктов без очистки NVS; 2) отказ входа и каждой административной операции наблюдателю; 3) отклонение неверного пароля/CSRF/подтверждения; 4) все три типа backup/restore; 5) повреждённая копия не меняет данные; 6) оба вида сброса; 7) AP при ошибочном Wi-Fi и статический IPv4; 8) выключенные выходы после операций; 9) прерывание питания на разных этапах записи/восстановления; 10) обычное OTA после первичной USB-установки. До проверки не подключайте силовые нагрузки.

Копии настроек содержат незашифрованные пароли. Храните защищённо. Не открывайте HTTP-порт контроллера в интернет.
